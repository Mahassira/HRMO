# ربط GitHub بـ Azure (مرة واحدة، نحو 10 دقائق)

بعد هذا الربط يُنشر كل تعديل يُدمج في `main` على Azure تلقائياً عبر سير العمل **Deploy to Azure**. لا تُحفظ أي كلمة مرور أو مفتاح في GitHub: يقبل Azure رموزاً قصيرة العمر تأتي فقط من الفرع `main` في هذا المستودع، والصلاحية محصورة في مجموعة موارد واحدة.

## المتطلبات

- اشتراك Azure أنت فيه **Owner**.
- صلاحية إنشاء تسجيل تطبيق ومجموعة في Microsoft Entra ID (متاحة افتراضياً للحساب الذي أنشأ المستأجر).
- صلاحية إدارة هذا المستودع على GitHub.

## الخطوات

**1. شغّل سكربت الإعداد في Azure.** افتح <https://shell.azure.com> واختر **Bash** ثم نفّذ:

<div dir="ltr">

```bash
curl -sL https://raw.githubusercontent.com/Mahassira/HRMO/main/infra/setup.sh -o setup.sh
LOCATION=westeurope bash setup.sh
```

</div>

اجعل `LOCATION` منطقة Azure التي يجب أن تُحفظ فيها البيانات. السكربت ينفّذ:

| الخطوة | ما ينشئه | السبب |
|---|---|---|
| 1 | تسجيل مزوّدي الموارد | ليتمكن الاشتراك من إنشاء موارد الويب وSQL والتخزين والمراقبة |
| 2 | مجموعة الموارد `hrmo-rg` | كل ما يخص HRMO فيها، وحذفها يزيل كل شيء |
| 3 | تسجيل التطبيق `hrmo-github-deploy` | الهوية التي يستخدمها GitHub |
| 4 | اعتماد موحّد | يقبل Azure الرموز من `Mahassira/HRMO` والفرع `main` فقط |
| 5 | دور Owner على `hrmo-rg` وحدها | لا وصول لأي شيء آخر في الاشتراك |
| 6 | المجموعة `HRMO SQL Admins` وأنت عضو فيها | وحدهم يديرون قاعدة البيانات |

**2. انسخ القيم الأربع التي يطبعها إلى GitHub.** في المستودع: **Settings ← Secrets and variables ← Actions ← Variables ← New repository variable**.

| الاسم | القيمة |
|---|---|
| `AZURE_CLIENT_ID` | يطبعها السكربت |
| `AZURE_TENANT_ID` | يطبعها السكربت |
| `AZURE_SUBSCRIPTION_ID` | يطبعها السكربت |
| `SQL_ADMIN_GROUP_ID` | يطبعها السكربت |

هذه معرّفات وليست أسراراً، لذلك توضع في **Variables**.

**3. شغّل النشر.** **Actions ← Deploy to Azure ← Run workflow**. التشغيل الأول يستغرق نحو 5 إلى 10 دقائق، ويظهر عنوان الموقع في ملخص التشغيل.

**4. أنشئ جداول قاعدة البيانات (عند أول نشر فقط).** في بوابة Azure افتح قاعدة البيانات `hrmo` ← **Query editor**، وادخل بحسابك، والصق محتوى `db/schema.sql` وشغّله. ثم شغّل سطرَي الخطوة 0 من الملف نفسه باسم تطبيق الواجهة البرمجية الظاهر في ملخص التشغيل.

## متغيرات اختيارية

| الاسم | الافتراضي | الاستخدام |
|---|---|---|
| `SWA_SKU` | `Standard` | `Free` لتجربة بلا كلفة (دون ضمان توافر) |
| `SQL_SKU` | `Basic` | `S0` أو `S1` إن كانت الاستعلامات بطيئة |
| `AZURE_RESOURCE_GROUP` | `hrmo-rg` | فقط إن غيّرت `RG` في السكربت |

## إن فشل التشغيل

| الرسالة | السبب | الحل |
|---|---|---|
| `AADSTS70021` أو لا يوجد اعتماد موحّد مطابق | اسم المستودع أو الفرع يختلف عن الاعتماد | أعد تشغيل السكربت مع `REPO=owner/name` كما يظهر في GitHub تماماً |
| `AuthorizationFailed` | الدور لم يُفعَّل بعد، أو السكربت لم يُشغَّل بصلاحية Owner | انتظر دقائق وأعد تشغيل سير العمل |
| `LocationNotAvailableForResourceType` | خدمة غير متاحة في المنطقة المختارة | أعد تشغيل السكربت بمنطقة `LOCATION` أخرى ومجموعة `RG` جديدة |
| المهمة متخطّاة (skipped) | المتغيرات ناقصة | راجع الخطوة 2 |

## إزالة كل شيء

احذف مجموعة الموارد `hrmo-rg` وتسجيل التطبيق `hrmo-github-deploy` والمجموعة `HRMO SQL Admins`. تتوقف الفوترة عند حذف مجموعة الموارد.

## الوضع الحالي

سير العمل ينشر البنية والواجهة. الواجهة ما زالت نسخة العرض ببيانات وهمية إلى أن تُنشر الواجهة البرمجية (المرحلة الثانية). كُتب هذا الإعداد دون اشتراك Azure للاختبار، فأول تشغيل هو اختباره الفعلي الأول.
