# نظام HRMO — المرجع الوظيفي

> **الإصدار:** 0.1 (الأساس) · **الحالة:** مسودة للمراجعة · **اللغة:** العربية ([English](../en/system-reference.md))
>
> **الملف المرافق:** [`data/config-defaults/policy-defaults.json`](../../data/config-defaults/policy-defaults.json)
>
> **ملاحظة:** معرّفات القواعد ومفاتيح الإعداد تبقى بالإنجليزية لأنها تُستخدم في الكود والاختبارات.

---

## 0. عن هذه الوثيقة

### 0.1 الغرض
هذه الوثيقة هي **المرجع الوظيفي** لنظام HRMO. وهو نظام قابل للتهيئة لإدارة الموارد البشرية في المؤسسات الإنسانية وغير الربحية التي يصل عدد موظفيها إلى نحو 800 موظف، ويُبنى على Microsoft Power Platform (Dataverse وPower Apps وPower Automate وPower BI).

تحدد الوثيقة **ما يجب أن يفعله النظام**: قواعد العمل، ومسارات الإجراءات، والموافقات، والنماذج، والتنبيهات، ومعاملات الإعداد التي تقف خلفها. أما التصميم التقني (الجداول والأعمدة وأدوار الأمان والـ Flows) فيُشتق منها في وثائق تصميم منفصلة.

### 0.2 المصدر وطريقة التعامل معه
استُخرجت القواعد من دليل سياسات فعلي للموظفين المحليين في مؤسسة إنسانية دولية. ولكي يكون المنتج عاماً، واحتراماً لحقوق مالك المصدر:

- لا يتضمن المرجع اسم أي مؤسسة أو هويتها البصرية أو أسماء أشخاص أو بيانات اتصال أو روابط أو أسماء أنظمة داخلية.
- لا يُنقل أي نص من نصوص السياسات. القواعد **استُخرجت وأعيدت صياغتها** كمتطلبات نظام.
- القيم الخاصة بدولة بعينها (أيام العمل، العطل، مواقع البدل اليومي، المراجع القانونية) تُعامل كـ **قيم نموذجية** داخل "مجموعة سياسات قُطرية" قابلة للتهيئة.
- السياسات السردية (مدونة السلوك، التحرش، الاحتيال، الحماية...) **لا تُشحن كنصوص**. يوفّر النظام "مكتبة سياسات" يرفع إليها كل عميل وثائقه الخاصة ويتتبّع الإقرار بها.

> ⚠️ **القيم الافتراضية أمثلة وليست استشارة قانونية.** على كل عميل مطابقتها مع سياساته ومع قانون العمل في كل دولة يعمل فيها.

### 0.3 كيف تُقرأ القواعد

| الحقل | المعنى |
|---|---|
| **المعرّف (ID)** | معرّف ثابت مثل `LV-012`، يُستخدم في تعليقات الكود والاختبارات وطلبات التغيير. |
| **القاعدة** | ما يفرضه النظام أو يدعمه. |
| **المعامل** | مفتاح الإعداد في `policy-defaults.json`. |
| **الافتراضي** | القيمة التي تأتي مع القالب الافتراضي. |
| **التطبيق** | `Block` = يمنع النظام الإجراء · `Warn` = يُسمح به مع تحذير ومبرر · `Track` = يُسجَّل ويظهر في التقارير فقط · `Notify` = يُطلق تنبيهاً. |

كل المعاملات **مؤرخة السريان** (`validFrom` و`validTo`)، وتنتمي إلى **مجموعة سياسات قُطرية**، ويمكن تخصيصها لكل **فئة توظيف**.

## 4. التوظيف والاختيار

### 4.1 مسار العمل

```
طلب احتياج ─► اعتماد ─► إعلان الوظيفة ─► الطلبات
     ─► القائمة الطويلة (الموارد البشرية) ─► القائمة القصيرة (القسم + مدير التوظيف)
     ─► لجنة المقابلة + الاختبارات ─► نماذج تقييم فردية
     ─► الترتيب والتوصية ─► اعتماد رئيس المكتب
     ─► فحص المراجع ─► فحص الامتثال ─► العرض الوظيفي
     ─► العقد والوصف الوظيفي ─► الاستقبال
```

## 23. خارج النطاق (الإصدار الأساسي)

- حساب الرواتب القانوني (ضريبة الدخل، الضمان الاجتماعي). النظام يصدّر مدخلات رواتب مدققة بدلاً من ذلك.
- استقبال بلاغات المخالفات أو الحماية أو الاحتيال أو الاتجار بالبشر والتحقيق فيها، فهذه تتولاها قناة العميل المستقلة.
- المشتريات وفحص الموردين والدفاتر المالية (وحدة الفحص تغطي **الموظفين** فقط).
- إجراءات الهوية والظهور والعلاقات الإعلامية وضوابط التصدير (تُغطى فقط كسياسات في مكتبة السياسات).
- برمجيات تشغيل أجهزة البصمة (النظام يستورد ملفات الأجهزة، وموصلات المزودين إضافات اختيارية).
